# speckit-enhanced — Test Scenarios

## Scenario 1: NL → Valid OpenAPI Spec (Happy Path)

**Input:**
```
description: "CRUD API for blog posts with JWT auth. Posts have title, body, author_id, tags. 
Support list (with pagination), create, get by ID, update, and delete operations."
base_url: https://api.blog.example.com/v1
```

**Expected Output:**
- Valid OpenAPI 3.0.3 YAML
- Paths: `/posts` (GET, POST), `/posts/{id}` (GET, PUT/PATCH, DELETE)
- All 5 operations have 200/201 + 4xx responses
- `components/schemas/Error` defined (RFC 7807 style)
- JWT BearerAuth security scheme defined
- At least one example per operation
- Validation score ≥ 6/7 gates passed (≥ 0.86)
- Confidence ≥ 0.70

**Acceptance criteria:**
- `openapi-spec-validator` returns 0 errors
- File written successfully to disk
- CLI exits code 0

## Scenario 2: 7-Gate Spec Validator — Incomplete Spec

**Input:** A deliberately incomplete OpenAPI spec with:
- No 4xx responses on any operation
- No `components/schemas` (thus no error schema)
- No security scheme defined
- No descriptions on operations
- No `info.version`

**Expected Output:**
- Validation score ≤ 0.30 (≤2/7 gates pass)
- Issues list contains:
  - `ERROR` on `AUTH_COVERAGE` (no security scheme)
  - `ERROR` on `VERSIONING` (missing info.version)
  - `ERROR` on `ERROR_SCHEMAS` (no error schema)
  - `WARN` on `STATUS_CODES` (no 4xx)
  - `WARN` on `DESCRIPTIONS`
  - `WARN` on `EXAMPLES`
- Report markdown file contains all issues with suggestions
- CLI reports validation score and failed gates

**Acceptance criteria:**
- All 6 expected issue gates are present in the output
- No spec file exported (ERROR gates block it)

## Scenario 3: pytest Test Stub Generation + Syntax Validity

**Input:** A valid user-profile CRUD spec (GET /users, POST /users, GET /users/{id}, PUT /users/{id}, DELETE /users/{id}) with JWT auth and Error schema.

**Expected Output:**
- pytest stubs file containing:
  - 5+ `async def test_` functions (≥1 per endpoint)
  - Happy path tests (200/201)
  - 401 unauthorized tests
  - 404 not-found tests (for ID-based operations)
  - 422 validation error tests (for POST/PUT)
- `python -m ast <file>` exits code 0 (syntactically valid)
- `test_count ≥ 10`

**Acceptance criteria:**
- Generated file passes `ast.parse()`
- At least 5 distinct test function names
- `operations_covered = 5`

## Scenario 5: Pattern Advisor — Real-Time Notification Use Case

**Input:**
```
use_case: "We need an API for a live chat application where users send messages and 
receive real-time notifications. Also need to store message history and user profiles."
constraints: {"team_expertise": "REST-heavy", "latency_sla_ms": 100}
```

**Expected Output:**
- `recommendation: "REST+AsyncAPI"` (or "AsyncAPI" acceptable)
- `confidence ≥ 0.60`
- Rationale mentions: real-time, WebSocket/event-driven, REST for CRUD
- `starter_spec_snippet` contains AsyncAPI or combined YAML fragment
- `trade_offs` dict present for all 3 protocols

**Acceptance criteria:**
- Recommendation is NOT pure "REST" (real-time signals detected)
- JSON is parseable with all required keys

## Scenario 6: Code → Spec Reverse Engineering (Flask)

**Input Python code:**
```python
from flask import Flask, request, jsonify
app = Flask(__name__)

@app.route('/users', methods=['GET'])
def list_users():
    return jsonify(users=[])

@app.route('/users', methods=['POST'])
def create_user():
    return jsonify(id=1), 201

@app.route('/users/<int:user_id>', methods=['GET'])
def get_user(user_id):
    return jsonify(id=user_id)
```

**Expected Output:**
- OpenAPI spec with paths: `/users` (GET, POST) and `/users/{user_id}` (GET)
- Confidence ≥ 0.50 (lower expected for reverse engineering)
- Warning: "Generated by reverse engineering — review for completeness"
- All 3 routes detected

**Acceptance criteria:**
- `paths` contains at least `/users` with GET and POST
- Warning message present

## Scenario 8: REST API Full Integration (FastAPI Server)

**Input:** Start the FastAPI server and send requests to all 7 endpoints.

**Test sequence:**
1. `GET /health` → `{"status": "ok"}`
2. `POST /api/v1/generate` with body `{"description": "CRUD user API"}` → spec YAML
3. `POST /api/v1/validate` with returned spec → score ≥ 0.50
4. `POST /api/v1/test-stubs` with returned spec, `framework="both"` → pytest + Jest stubs
5. `POST /api/v1/advise` with `{"use_case": "IoT sensor telemetry streaming"}` → recommendation includes AsyncAPI
6. `GET /api/v1/cost` → `{"total_usd": ..., "call_count": ...}`
7. `GET /metrics` → Prometheus text format with `speckit_generate_requests_total`

**Acceptance criteria:**
- All 7 requests return HTTP 200
- No server errors (500) in logs
- `/metrics` output contains expected counter names
